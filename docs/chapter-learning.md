# Material-based chapter quests

The quest screen starts with the three material subjects: Algorithms, Data structures and Connectionist AI. **Chapter quests** opens a readable, pannable chapter sequence in the same order as the numbered Source chapters. Algorithms has 11 chapters (including Python); Data structures and Connectionist AI each have 10. Each subject retains its short game orientation and final boss. **Overview** returns to the subject map; **Center**, zoom, pointer dragging and keyboard navigation remain available.

Each chapter follows this sequence:

1. **Concept:** a specific learning goal and a concise explanation.
2. **Worked example:** a trace, calculation, code example or concrete scenario, including its result and reasoning.
3. **Guided practice:** a different applied problem with explanatory feedback and unlimited safe retries.
4. **Chapter check:** the existing encounter checks understanding using that chapter's question pool. The story supplies the investigation context.

The full Source chapter remains one explicit **Read chapter** or **Reference book** action away. Books, notes and bookmarks retain their existing behavior. Study and practice can be explored ahead; the encounter still requires previous investigation objectives. New chapter encounters open the learning sequence until guided practice is complete. Existing activity completions are retained without inventing practice attempts or forcing a repeat of earned encounters.

Practice never spends HP/focus or awards character XP. A correct guided response records `guided-practice-<chapter-id>` as evidence, separately from correct unaided combat answers. Reading an example or answering practice alone does not complete a chapter's encounter, claim a reward, reveal a clue or unlock a boss. Character XP continues to come from the existing first-clear encounters and branch rewards.

## Content and saves

`content/11-algorithm-chapters.md`, `12-structure-chapters.md` and `13-ai-chapters.md` contain the 31 authored chapter quests. They are not regenerated by Source import. A chapter has `kind: chapter`, `branch`, `lesson`, ordered quest `prerequisites`, existing activity `objectives`, zero XP and a `learning` block:

```yaml
learning:
  goal: Predict how a loop changes a variable.
  concept: A short explanation of the mechanism.
  example: A worked example written in Markdown.
  practice:
    prompt: A distinct applied problem.
    options: [First answer, Second answer, Third answer, Fourth answer]
    answer: 1
    explanation: Why the second answer follows from the mechanism.
```

Worked examples support Markdown tables and code. Nested code fences in YAML block strings are preserved; record delimiters must start at column zero. The compiler validates lesson/branch/activity references, chapter ownership, prerequisite cycles and practice answer bounds.

The journal's `chapterProgress` records example acknowledgment, successful practice and attempt counts. Old saves default to an empty record. Imports reject unknown chapters and inconsistent practice states before overwriting existing progress. Guided evidence is deduplicated, while attempts remain useful for review. The two existing story branches and their stable IDs remain intact.
